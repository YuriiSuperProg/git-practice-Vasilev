1. НАСТРОЙКА GIT (выполняется один раз)

git --version
    Проверка установленной версии Git.

git config --global user.name "ваш_ник"
    Установка имени пользователя для подписи коммитов.

git config --global user.email "ваша_почта@yandex.ru"
    Установка email для подписи коммитов.

git config --list
    Просмотр всех текущих настроек Git.

2. СОЗДАНИЕ И ИНИЦИАЛИЗАЦИЯ РЕПОЗИТОРИЯ

mkdir Lab2_ISRPO_FIO
    Создание папки проекта.

cd Lab2_ISRPO_FIO
    Переход в папку проекта.

git init -b main
    Создание нового локального репозитория с основной веткой main.
    Создаётся скрытая папка .git со служебной информацией.

pwd
    Показать текущий путь (в какой папке находимся).

ls
    Показать содержимое текущей папки.

3. ПРОВЕРКА СОСТОЯНИЯ И ИНДЕКСАЦИЯ

git status
    Показывает состояние репозитория:
    - какие файлы изменены;
    - какие добавлены в индекс;
    - какие не отслеживаются (Untracked, буква U).

git add .gitignore
    Добавить конкретный файл в индекс (staging area).

git add Program/Program.cs
    Добавить конкретный файл по пути.

git add .
    Добавить ВСЕ изменения (кроме игнорируемых) в индекс.

4. СОЗДАНИЕ КОММИТОВ

git commit -m "Initial commit: create console app"
    Создать коммит с сообщением.
    При первом коммите появляется пометка (root-commit).

git commit -am "message"
    Добавить изменения отслеживаемых файлов и сразу закоммитить
    (не работает для новых файлов).

git log
    Полная история коммитов: хеш, автор, дата, сообщение.
    Выход из просмотра — клавиша q.

git log --oneline
    Компактная история: сокращённый хеш (7 символов) + сообщение.
    Удобно для быстрого просмотра.

git show <хеш>
    Детальная информация о конкретном коммите:
    - полный хеш, автор, дата;
    - diff: какие строки добавлены (+) и удалены (-).

5. ИГНОРИРОВАНИЕ ФАЙЛОВ (.gitignore)

.gitignore — файл, в котором перечисляются файлы и папки,
которые Git не должен отслеживать.

Пример содержимого .gitignore:

    bin/
    obj/
    .vs/

Пояснение:
    bin/  — скомпилированные файлы .NET;
    obj/  — временные файлы сборки;
    .vs/  — служебная папка Visual Studio.

Эти папки восстанавливаются автоматически и не должны
попадать в репозиторий.

6. РАБОТА С УДАЛЁННЫМ РЕПОЗИТОРИЕМ (GitHub)

git remote add origin https://github.ru/project/логин/репозиторий.git
    Привязать удалённый репозиторий к локальному.
    origin — стандартное имя удалённого репозитория.

git remote -v
    Показать адреса удалённых репозиториев (fetch и push).

git push -u origin main
    Отправить ветку main на сервер и связать её с origin/main.
    Флаг -u включает отслеживание: далее можно писать просто
    git push и git pull.

git push
    Отправить изменения (после настройки -u).

git pull
    Забрать изменения с сервера и слить с локальными.

git fetch --prune
    Загрузить информацию об удалённых ветках и удалить ссылки
    на несуществующие удалённые ветки.

7. РАБОТА С ВЕТКАМИ

git branch
    Список локальных веток. Звёздочка (*) — текущая ветка.

git branch -a
    Список ВСЕХ веток: локальных и удалённых (remotes/origin/...).

git switch -c feature
    Создать ветку feature и сразу переключиться на неё.
    (Современный аналог: git checkout -b feature)

git switch main
    Переключиться на существующую ветку main.

git switch -
    Переключиться на предыдущую ветку.

git branch hotfix
    Создать ветку hotfix без переключения.

git branch -d hotfix
    Безопасно удалить ветку (если изменения слиты).

git branch -D hotfix
    Принудительно удалить ветку (даже если не слита).

git push -u origin feature
    Отправить ветку feature на удалённый сервер.

8. СЛИЯНИЕ ВЕТОК (PULL REQUEST НА GitHub)

На GitFlic:
    1. Заходим на нужный репозиторий.
    1. Вкладка "Запросы на слияние" (Pull Requests).
    2. "Создать "New pull "request".
    3. Источник: feature, Цель: main.
    4. Заголовок и описание.
    5. Опции: "Удалить исходную ветку после слияния",
       "Выполнить слияние одним коммитом (Squash)".
    6. Создать → Слить (Merge).

После слияния локально:

git switch main
    Переключиться на main.

git pull
    Обновить main с сервера.

git fetch --prune
    Удалить ссылки на несуществующие удалённые ветки.

git branch -d feature
    Удалить локальную ветку feature после слияния.
